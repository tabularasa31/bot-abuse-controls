# DDoS-защита — справочник правил и сигналов

Правила и сигналы DDoS-слоя в формате «если условие → действие», по всем трем
подслоям. Контракт поведения — [ddos-spec.md](ddos-spec.md); словарь сущностей —
[ddos-entities-reference.md](ddos-entities-reference.md).

**Природа объектов разная** (в отличие от каскада, где все — access-фазовый вердикт):

- **rate-rule / adaptive** — L7-логика поверх каскада (rate-limit, challenge,
  адаптивный `attack_mode`, репутация). Может влиять на судьбу запроса.
- **mitigation-directive** — реальный отказ/обрыв соединения, его делает nginx или
  пропатченный билд; вердикта каскада нет (есть HTTP-код отказа или обрыв на
  frame-уровне).
- **log-signal** — наблюдение в log-фазе: Lua видит результат nginx-дропа и пишет
  лог-событие (запрос уже оборван).
- **tag** — namespace-метка на лог-событии; судьбу запроса не решает, питает
  репутацию.
- **escalation** — поставка нарушителя в общий сток репутации / сетевой ACL-feed.

## A. L7 application-layer — база (каскад)

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| A1 | частота запросов по ключу (IP / IP+UA / API / отпечаток / recon-URL) превысила окно GCRA | challenge или отказ по политике хоста | rate-rule |
| A2 | клиент под нагрузкой не решает выданный challenge | запрос не проходит; источник копит «нерешенные» | rate-rule |
| A3 | для хоста вручную установлен `attack_mode=on` | повышенная строгость: ниже пороги, агрессивнее challenge | rate-rule |

## B. L7 application-layer — адаптивность (этот слой)

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| B1 | доля «плохого» трафика хоста (боты / solve-rate ≈ 0 при многих challenge / рост латентности origin) превысила базлайн | авто-взвод `attack_mode` хоста | adaptive |
| B2 | «плохой» трафик спал ниже базлайна и держится | авто-снятие `attack_mode` **с гистерезисом** | adaptive |
| B3 | для хоста `attack_mode` установлен вручную | ручная установка приоритетна над авто (авто не перебивает) | adaptive |
| B4 | IP / /24 / ASN — повторный нарушитель по сигналам всех слоев | +репутация в **глобальный** артефакт subnet/IP/ASN (soft: +score/строгость, не блок) | adaptive |
| B5 | под `attack_mode` хоста подсеть с плохой репутацией И solve-rate ≈ 0 | временная эскалация challenge → drop для /24; TTL + авто-снятие после спада | adaptive |
| B6 | источник (fp/subnet) активно атакует тенанта и подтвержден | публикация в short-TTL **кросс-тенантный hot-list** (высокий порог промоута) | escalation |
| B7 | fp/subnet есть в кросс-тенантном hot-list | все эджи пред-взведены: challenge-first, ниже порог (даже без локальной атаки) | adaptive |

## C. Connection/protocol — slow-attacks, митигация (nginx)

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| C1 | клиент не дослал заголовки в пределах `client_header_timeout` (10–15s) | nginx рвет соединение, `408` | mitigation-directive |
| C2 | клиент медленно/никогда не завершает тело в пределах `client_body_timeout` | nginx рвет соединение, `408` | mitigation-directive |
| C3 | клиент медленно вычитывает ответ дольше `send_timeout` (slow read) | nginx рвет соединение | mitigation-directive |
| C4 | число одновременных соединений с одного `$binary_remote_addr` превысило cap зоны `limit_conn` | nginx отказывает новым соединениям кодом `limit_conn_status` (`503`) | mitigation-directive |
| C5 | keepalive-соединение обслужило больше `keepalive_requests` / простояло дольше `keepalive_timeout` | nginx закрывает keepalive-соединение | mitigation-directive |

## D. Connection/protocol — slow-attacks, наблюдение (log-фаза)

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| D1 | в log-фазе `$status=408` (таймаут заголовков/тела; slow read по `send_timeout` обрывается без 408) | лог-событие с тегом `slow_client`; +счетчик по IP / /24 | log-signal |
| D2 | в log-фазе `$status` = `limit_conn_status` (`503`, отказ `limit_conn`) | лог-событие с тегом `conn_flood`; +счетчик по IP / /24 | log-signal |
| D3 | накопленный по IP / /24 счетчик `slow_client`/`conn_flood` указывает на повторного нарушителя | сигнал в общий сток репутации → при тяжести эскалация в edge-ACL feed | escalation |

## E. Connection/protocol — slow-attacks, policy-ручка (опционально)

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| E1 | для хоста `attack_mode=on` (или повышенная строгость) | `map`-driven выбор более жесткой зоны `limit_conn` / меньших таймаутов (per-host, не per-request) | mitigation-directive |

## F. Connection/protocol — HTTP/2 DoS

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| F1 | клиент дешево создает и тут же отменяет HTTP/2-стримы сверх порога (Rapid Reset) | пропатченный билд (≥ 1.25.3) считает сброшенные стримы и рвет соединение | mitigation-directive |
| F2 | число одновременных HTTP/2-стримов превысило `http2_max_concurrent_streams` | nginx ограничивает число параллельных стримов | mitigation-directive |
| F3 | CONTINUATION / PING / SETTINGS flood превышает пороги версии билда | пропатченный билд применяет защиту по этим порогам | mitigation-directive |
| F4 | идентификация HTTP/2-клиента видит аномальные SETTINGS/stream-паттерны (если доступна) | h2-abuse как сигнал в репутацию/score; verdict не эмитится | tag |

## G. Волюметрика L3/L4 — контракт

| # | Если | → действие | Категория |
| --- | --- | --- | --- |
| G1 | IP / /24 подтвержден как нарушитель (накоплено из L7 и connection/protocol сигналов) | поставка в edge-ACL feed; сетевую митигацию выполняет внешний слой | escalation |
| G2 | волюметрический флуд (SYN/UDP/амплификация) до рукопожатия | вне периметра прокси — прокси не точка митигации | (граница) |

## Сводка по подслоям

| Подслой | Защита | Вклад слоя |
| --- | --- | --- |
| L7 rate-based | каскад (rate-limit/challenge/attack_mode) | адаптивность: авто-attack-mode, репутация подсетей, hot-list |
| connection/protocol | nginx-директивы + версия билда | наблюдение (log-сигналы) + эскалация в репутацию |
| волюметрика L3/L4 | сетевой слой вне прокси | поставка кандидатов в edge-ACL feed |

## Границы (что эти правила НЕ делают)

- **Не блокируют connection/protocol из Lua** — реальный отказ у nginx/билда; Lua
  наблюдает (log-фаза) и питает репутацию.
- **Не дают adaptive per-request лимиты соединений** — nginx-директивы статичны;
  policy-ручка переключает зоны грубо (per-host / global).
- **Не митигируют волюметрику L3/L4** — хендшейк к этому моменту уже не состоялся;
  максимум — контракт edge-ACL feed.
- **Авто-attack-mode не перебивает ручной** и снимается с гистерезисом.
