# API и Account Protection — словарь сущностей

Канонический словарь терминов, стадий, ключей, профилей, каталогов, тегов, полей лога
и перечислений слоя. Контракт поведения — [api-spec.md](api-spec.md); правила —
[api-rules-reference.md](api-rules-reference.md).

---

## 1. Оси и общие термины

| Термин | Определение |
| --- | --- |
| Ось A (abuse аккаунтов и API) | контроль credential stuffing, brute force, фейк-регистрации, scraping, abuse/утечки ключей, enumeration — по идентичности и квотам. |
| Ось B (контракт и governance) | позитивная модель: что разрешено на эндпоинте (метод/тип/схема/токен) + ресурсные лимиты, edge-валидация токена, транспортная гигиена, инвентарь. |
| identity-blind | свойство каскада: он видит IP/fp/UA/Host/путь/заголовки, но не «какой аккаунт/ключ». Отсюда нужна стадия извлечения идентичности. |
| позитивная модель | описывает разрешенное и режет прочее (ось B). Комплементарна негативной модели WAF (сигнатуры атак). |
| mode-gated | при shadow срабатывание считается и логируется, но запрос не режется; при active — исполняется. |
| декларация эндпоинтов | per-host список путей логина/регистрации/API (glob) + опц. per-endpoint квоты. Стадии идентичности и контракта работают только на объявленных путях. |
| endpoint class | классификатор эджа «какой класс у пути» (login / register / api / прочее), из декларации. |

## 2. Идентичность (фундамент оси A)

| Сущность | Определение |
| --- | --- |
| стадия извлечения идентичности | легкая стадия на объявленных путях: кладет нормализованный hashed-ключ в контекст запроса (как rate по fp кеит на fp). Вердикт не выносит. |
| hashed-username | username из формы логина, хешированный HMAC. Ключ для профиля логина и failed-auth. Сырьем не используется и не логируется. |
| hashed-key | API-ключ/bearer-токен из заголовка/query, хешированный HMAC. Ключ для профиля ключа и репутации. |
| graceful skip | если идентичность не извлечена — зависящие профили пропускаются, запрос продолжает каскад без ошибки. |
| PII-инвариант | username/токен — только хешированно; пароль не логируется/не хранится/не инспектируется; чтение тела только на login-путях, с лимитом и bypass для upload. |

## 3. Rate-профили по идентичности (ось A)

| Сущность | Определение |
| --- | --- |
| профиль логина (per-account) | GCRA-профиль по hashed-username: ловит стаффинг по многим аккаунтам и brute force одного. Тег `account:cred_stuffing`. |
| профиль ключа (per-key) | GCRA-профиль по hashed-ключу: ловит abuse ключа с многих IP, scraping, enumeration, утечку ключа. Тег `api:key_abuse`. |
| движок rate-лимита | тот же GCRA-движок и shared-memory ячейки, что у сетевых профилей каскада; меняется только ключ (идентичность вместо сетевого параметра). |

## 4. Failed-auth feedback (ось A)

| Сущность | Определение |
| --- | --- |
| failed-auth | запрос к login-пути, на который origin ответил 401/403 (response-фаза). |
| failed-ratio | доля неуспешных логинов по hashed-аккаунту или /24-подсети за окно. Всплеск → +score и эскалация. Тег `account:auth_fail_spike`. |
| допущение различимости статусов | feedback работает, если origin отдает различимые статусы на успех и неуспех; фиксируется при внедрении на домене. |

## 5. Контракт и схема (ось B)

| Сущность | Определение |
| --- | --- |
| allowed_methods | разрешенные HTTP-методы эндпоинта (позитивная модель). Прочее → reject. Тег `api:contract_violation`. |
| allowed_content_types | разрешенные content-type тела эндпоинта. |
| required_params | обязательные параметры эндпоинта; их отсутствие → reject. |
| schema-каталог | компилированное подмножество JSON-схем (типы, required, `additionalProperties`), доставляется как slow-каталог, PR-only. Тег `api:schema_violation`. |
| `additionalProperties=false` | поля вне схемы запрещены — отсекает mass-assignment-вектор на входе (но не семантику mass-assignment — это backend). |
| schema bypass | список upload/бинарных эндпоинтов, где тело не парсится как JSON. |

## 6. Resource limits (ось B)

| Сущность | Определение |
| --- | --- |
| лимит размера тела | per-host/per-endpoint; превышение → 413 (часть на уровне nginx, до Lua). |
| структурная сложность JSON | максимальная глубина вложенности и длина массивов; защита от «billion laughs». Превышение → 422. |
| лимиты GraphQL (опц.) | глубина / стоимость / число алиасов запроса. |

## 7. Edge JWT и mTLS (ось B)

| Сущность | Определение |
| --- | --- |
| JWT-валидация | stateless-проверка токена на API-путях: подпись (JWKS/секрет), `exp`/`nbf`, `iss`/`aud`. Невалидный → reject (401). Тег `api:token_invalid`. |
| JWKS / секрет | материал проверки подписи токена; доставляется как секрет/каталог. |
| required-scope (опц.) | per-endpoint required-scope = coarse authz (не полный BFLA). |
| mTLS / client-cert | проверка клиентского сертификата на mTLS-хостах (опц., per-tenant), транспортный уровень. Тег `api:mtls_fail`. |

## 8. Transport-гигиена и инвентарь (ось B)

| Сущность | Определение |
| --- | --- |
| security-заголовки | HSTS, X-Content-Type-Options, корректный CORS по политике (не `*` вслепую). Response-side. |
| banner-срезка | удаление banner-заголовков и раскрытия версии сервера. |
| маскировка ошибок | сокрытие многословных 5xx-деталей origin в ответе клиенту. |
| shadow-эндпоинт | вызываемый путь вне объявленных. Тег `api:shadow_endpoint`; опц. draft-PR в декларацию. |
| zombie-эндпоинт | объявленный, но не вызываемый за окно (кандидат на вывод из контракта). |
| deprecated-version | путь, помеченный устаревшим; запрос → 410 (mode-gated). |

## 9. Теги (копятся в поле `tags` лога, формат `account:*` / `api:*`)

| Тег | Где появляется | Что означает |
| --- | --- | --- |
| `account:cred_stuffing` | rate_limits (профиль логина) | всплеск попыток логина по аккаунтам |
| `account:auth_fail_spike` | log/response (failed-auth) | всплеск доли неуспешных логинов |
| `api:key_abuse` | rate_limits (профиль ключа) | abuse одного ключа (scraping/enumeration/утечка) |
| `api:contract_violation` | per-endpoint contract | метод/тип/параметр вне разрешенного |
| `api:schema_violation` | schema-валидация | тело не проходит JSON-схему |
| `api:token_invalid` | edge JWT | невалидный/протухший токен |
| `api:mtls_fail` | mTLS | нет/невалиден клиентский сертификат |
| `api:shadow_endpoint` | API inventory | вызов необъявленного пути |

## 10. Поля политики и каталоги

| Сущность | Где живет | Назначение |
| --- | --- | --- |
| декларация путей | per-host политика | login/register/api пути (glob) + per-endpoint квоты |
| per-endpoint contract | per-host политика | allowed_methods / content_types / required_params |
| JWT-config | per-host политика | JWKS/секрет, ожидаемые iss/aud, required-scope |
| mTLS-флаг | per-host политика | включение проверки клиентского сертификата |
| transport-флаги | per-host политика | security-заголовки, banner-срезка, маскировка ошибок |
| deprecated-version | per-host политика | паттерны устаревших путей → 410 |
| schema-каталог | slow-каталог (PR-only) | JSON-схемы тел по эндпоинтам |
| disposable-email каталог | slow-каталог (PR-only) | домены одноразовой почты (сигнал фейк-регистрации) |

## 11. Перечисления

| Перечисление | Значения |
| --- | --- |
| категория правила | `blocking` · `soft` · `tag` · `—` (фундамент) |
| класс эндпоинта | `login` · `register` · `api` · прочее |
| HTTP при reject | 401 · 403 · 410 · 413 · 415 · 422 · 429 |

## 12. Технические границы (backend, не эдж)

| Сценарий | Почему не эдж | Где решается |
| --- | --- | --- |
| ATO (аномальный успешный вход) | нужна история аккаунта; эдж дает лишь fp/geo-контекст | backend |
| авторизация объектов/функций (BOLA / полный BFLA) | нужны identity + ownership + бизнес-правила | backend |
| business-logic abuse (скальпинг, купоны) | нужен app-контекст | приложение/backend |
| breached-password validation | полная проверка пароля по брешь-листу — не hot-path | backend |
| ревокация/интроспекция токена | требует state | backend |
