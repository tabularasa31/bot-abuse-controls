# Аналитика и блок-лист — словарь сущностей

Канонический словарь сущностей, полей и перечислений слоя аналитики. Контракт
поведения — [analytics-spec.md](analytics-spec.md); правила —
[analytics-rules-reference.md](analytics-rules-reference.md).

---

## 1. Отпечаток и его свойства

| Сущность | Определение |
| --- | --- |
| **fp (отпечаток)** | строка-идентификатор TLS-ClientHello клиента (порядок шифров/расширений/версий), фиксированного формата. Ключ всей агрегации слоя. |
| **cipher_count** | число шифров в рукопожатии; **фиксировано внутри одного fp** (часть токена). Браузерное значение — из узкого набора (по наблюдениям `{15,16,20}`). |
| **hashes** | хеш-компоненты токена; фиксированы внутри fp. Сверяются со словарями инструментов и с позитивным каталогом браузеров. |

## 2. Скоринг

| Сущность | Определение |
| --- | --- |
| **score** | аддитивная сумма сигналов (§ rules S1–S7). **Только ранжирует**, ничего не блокирует. |
| **signal (сигнал)** | отдельное слагаемое score (impersonator, suspicious cipher, automation UA, DC ASN, multi-IP, persistent, recon URI). |
| **tier (тир)** | категория по score: **HIGH ≥5 · MEDIUM 3–4 · LOW 1–2**. |
| **impersonator** | браузерный UA на отпечатке известного инструмента (маскировка). Самый весомый сигнал (+3); опора intent-правила. |
| **automation UA** | UA, который сам по себе инструмент (curl/python/go/okhttp/bot/scanner). |
| **recon URI** | обращение к типовым разведывательным путям (`/.env`, `/wp-login`, `/admin`, …). |

## 3. Гейты и связанные понятия

| Сущность | Определение |
| --- | --- |
| **gate (гейт)** | порог-вето допуска к промоуту. Гейты НЕ складываются и НЕ компенсируют друг друга. |
| **genuine browser** | событие, где **одновременно**: UA браузерный, число шифров браузерное, хеши НЕ из словаря инструментов. Признак настоящего браузера, а не маскировки. |
| **human_share** | доля genuine-browser событий среди всех событий fp. Основа purity-вето. |
| **purity (вето)** | гейт: `human_share` ≤ порога. Закрывает риск «неизвестный легит-браузер принят за бота». |
| **volume** | гейт: достаточно событий за время жизни И хотя бы один IP. Отсекает шум. |
| **allowlist (вето)** | гейт: ни одного allow-вердикта под fp И ни одного IP в whitelist (verified-bot/whitelist/валидный clearance). |
| **dedup** | гейт: fp еще нет в каталоге. |
| **intent (вето)** | гейт: `impersonator ИЛИ (recon И НЕ generic_honest_tool)`. Закрывает риск «заблокировали общий отпечаток инструмента». |
| **generic_honest_tool** | известный честный инструмент, не являющийся impersonator (например, обычный curl без браузерного UA). Его общий fp — у миллионов легитимных клиентов. |
| **known-good инвариант** | fp, совпавший с позитивным каталогом браузеров, **никогда** не авто-блокируется (anti-poisoning). |
| **auto_eligible** | пригоден к авто-промоуту: HIGH И достаточно дней И все гейты И intent. |

## 4. Каталожная запись и жизненный цикл

| Сущность | Определение |
| --- | --- |
| **catalog entry (запись блок-листа)** | пара `fp → status` в каталоге блок-листа + комментарий-паспорт над ней. |
| **status** | `staging` (match-but-observe, НЕ блокирует) \| `active` (enforce, блокировка 403). |
| **паспорт** | комментарий над записью: action, причина, score/тир, evidence chain, `human_share`, дата ревизии, план жизненного цикла. Аудит-след. |
| **promote** | переход candidate → `staging` (PR). |
| **activate** | переход `staging → active` (PR), по подтверждению наблюдением. |
| **demote** | переход `active → staging` (снятие enforcement) или удаление. |
| **remove** | удаление записи из каталога. |
| **TTL (порог неактивности)** | срок молчания, после которого fp — кандидат на снятие. **Не** enforced-протухание на эдже, а порог авто-детектора. |

## 5. Наблюдение

| Сущность | Определение |
| --- | --- |
| **staging_match** | пометка в потоке вердиктов: staged-паттерн fp сматчился в observe-only (не заблокировал). Наземная правда для `staging → active`. |
| **observation verdict** | итог наблюдения за staging-записью: **activate** (чисто → активировать) \| **fp_caught** (поймал легит → снять) \| **observe** (мало данных → ждать). |
| **окно наблюдения** | минимальные часы + минимум матчей, нужные чтобы судить об активации. |

## 6. Кандидаты, артефакты, состояние

| Сущность | Определение |
| --- | --- |
| **candidate (кандидат)** | fp с посчитанными score/тиром/гейтами/`auto_eligible`, попавший в отчет/артефакт. |
| **stale entry** | каталожная запись, молчащая дольше TTL — кандидат на снятие. |
| **артефакты решений** | машинно-читаемые срезы прогона: кандидаты, наблюдение за staging, кандидаты на снятие. Несут метку времени генерации. |
| **freshness guard** | защита автомата: если артефакты старше порога — не действовать. |
| **аккумулятор состояния** | персистентный per-fp срез того, что хранилище вердиктов за свой горизонт не помнит: накопленный объем событий и «последний раз виден». |
| **ротация состояния** | ограничение роста аккумулятора (архивация старого, отбрасывание low-signal, lazy-restore). **Исключение:** fp из каталога блок-листа от архивации освобождены. |

## 7. Сигналы детектора

| Сущность | Определение |
| --- | --- |
| **позитивный каталог браузеров** | справочник «известный-хороший»: хеши → семейство (и версия) браузера. Дает точную genuine-browser проверку и known-good инвариант. |
| **UA↔fp mismatch** | расхождение версии браузера, заявленной в UA, и версии по позитивному каталогу — сигнал маскировки без словаря инструментов. |
| **headless-каталог** | справочник отпечатков headless-стэков (Playwright/Puppeteer/undetected-chromedriver). |
| **solve_rate** | доля решенных challenge по fp. Низкая при большом числе выданных — сильный bot-сигнал и ускоренный гейт `staging → active`. |
| **поведенческие сигналы** | межзапросные интервалы (ритмичность), отсутствие человеческого разброса, навигационные графы. |

## 8. Перечисления

| Перечисление | Значения |
| --- | --- |
| **tier** | `HIGH` (≥5) · `MEDIUM` (3–4) · `LOW` (1–2) |
| **status** | `staging` · `active` |
| **observation verdict** | `activate` · `fp_caught` · `observe` |
| **gate verdict** | `pass` · `veto` |

## 9. Константы и ручки (контрактные пороги)

Конкретные значения — параметры реализации; контракт фиксирует их **смысл** и
направление.

| Параметр | Смысл | Ориентир |
| --- | --- | --- |
| порог purity | максимум `human_share` для допуска к блоку | низкий (порядка 5%) |
| минимум событий (volume) | сколько событий за время жизни нужно | порядка десятков |
| дней до входа в staging | минимум разных дней до promote | низкий (вход дешев — наблюдение на staging) |
| окно наблюдения staging | минимум часов в staging до активации | не меньше суток-двух (разный суточный трафик) |
| минимум матчей staging | сколько staging_match нужно для суждения | порядка десятка |
| TTL auto-demote | порог молчания для снятия | порядка двух недель (больше горизонта хранилища) |
| порог свежести артефактов | при каком возрасте автомат не действует | порядка суток |
