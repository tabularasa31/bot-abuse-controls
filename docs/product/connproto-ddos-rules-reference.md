# Connection/Protocol-level DDoS — каталог правил и сигналов

Полный перечень защитных правил и наблюдательных сигналов для класса
connection/protocol-level DDoS (slow-attacks + HTTP/2 DoS) в формате
«Если условие → действие». Источник правды по поведению —
[connection-protocol-ddos-spec.md](connection-protocol-ddos-spec.md); этот
документ — плоский справочник «что на что срабатывает».

**Статус:** проектный контракт (целевое поведение), предшествует реализации.

**Чем эта ось особенная.** Это **НЕ стадия каскада.** Правила каскада
(`hygiene`/`reputation`/`tls_fp`/`rate_limits`/`verification`) живут в
`access_by_lua` и эмитят access-фазовые вердикты. Защита здесь живёт **ниже**
этой точки: slow-клиент и сброшенный HTTP/2-стрим до `access_by_lua` не доходят,
поэтому добавлять стадию в `verdict.lua` некуда. «Правила» этой оси — это два
разных по природе объекта:

- **mitigation-directive** — собственно защита, её делает nginx (директивы) или
  пропатченный билд. Никакого Lua-вердикта здесь нет — есть HTTP-код отказа
  (408 на таймаут, отказ `limit_conn` под `limit_conn_status`, обрыв соединения
  на frame-уровне).
- **log-signal** — наш BAC-вклад: `log_by_lua`-хук видит nginx-дроп в log-фазе и
  превращает его в наблюдаемое событие `bac_log`.
- **tag** — метка на этом событии (`slow_client` / `conn_flood` / h2-abuse
  сигнал), которая питает дашборд и репутацию (D14 subnet/IP), а через неё —
  эскалацию в edge-ACL feed.

То есть схема всей оси: **nginx митигирует → Lua наблюдает → reputation
эскалирует**. Реальная блокировка — у nginx; наша ценность — превратить дроп в
сигнал и эскалировать его.

Обозначения:

- **Категория** — `mitigation-directive` (реальный отказ, делает nginx/билд),
  `log-signal` (событие `bac_log` из log-фазы), `tag` (метка на событии,
  verdict не эмитит).
- **Где живёт** — `nginx` (директива конфига), `build` (версия/патч OpenResty),
  `log_by_lua` (наш хук наблюдения).
- **Источник** — откуда берутся данные/триггер.
- **Этап** — этап внедрения (Baseline-директивы / Observability / Policy-ручка /
  HTTP/2 mitigation-аудит / h2-abuse как сигнал).

## A. Slow-attacks — mitigation-директивы (реальная защита)

Baseline-директивы: чистый nginx, 0 Lua, дают ~80% эффекта. Рвут или ограничивают
соединения, которые не доходят до access-фазы. Полностью обратимы.

| #  | Если…                                                                                                                | То…                                                                              | Категория            | Где живёт | Источник                          | Этап               |
| -- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | -------------------- | --------- | --------------------------------- | ------------------ |
| 1  | Клиент не дослал заголовки запроса в пределах `client_header_timeout` (срезан до 10–15s)                             | nginx рвёт соединение и отдаёт `408 Request Timeout`                             | mitigation-directive | nginx     | директива `client_header_timeout` | Baseline-директивы |
| 2  | Клиент медленно/никогда не завершает передачу тела запроса в пределах `client_body_timeout`                          | nginx рвёт соединение и отдаёт `408 Request Timeout`                             | mitigation-directive | nginx     | директива `client_body_timeout`   | Baseline-директивы |
| 3  | Клиент медленно вычитывает ответ дольше `send_timeout` (slow read)                                                   | nginx рвёт соединение                                                            | mitigation-directive | nginx     | директива `send_timeout`          | Baseline-директивы |
| 4  | Число одновременных соединений с одного `$binary_remote_addr` превысило cap зоны `limit_conn`                        | nginx отказывает новым соединениям кодом из `limit_conn_status` (503)            | mitigation-directive | nginx     | директива `limit_conn` + зона     | Baseline-директивы |
| 5  | Одно keepalive-соединение обслужило больше `keepalive_requests` запросов / простаивает дольше `keepalive_timeout`    | nginx закрывает keepalive-соединение (ограничивает удержание idle-слотов)        | mitigation-directive | nginx     | `keepalive_requests`/`keepalive_timeout` | Baseline-директивы |

## B. Slow-attacks — log-сигналы (наш слой наблюдения)

`log_by_lua`-хук читает то, что nginx отдаёт в log-фазе (`$status`,
`$request_time`, `$connection_requests`), и для дропов из таблицы A эмитит
событие `bac_log` с тегом. Переиспользует тот же `bac_log`-контракт, что
hygiene/reputation. Ограничение: видно только то, что попало в log-фазу — сам
процесс цежения соединения не виден.

| #  | Если…                                                                                                            | То…                                                                                      | Категория  | Где живёт   | Источник                                | Этап          |
| -- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------- | ----------- | --------------------------------------- | ------------- |
| 6  | В log-фазе `$status=408` (сработал один из header/body таймаутов из правил 1–2)                                 | событие `bac_log` с тегом `slow_client`; инкремент счётчика по IP / /24                  | log-signal | `log_by_lua` | `$status` / `$request_time`             | Observability |
| 7  | В log-фазе зафиксирован отказ `limit_conn` (`$status` = `limit_conn_status`, 503)                              | событие `bac_log` с тегом `conn_flood`; инкремент счётчика по IP / /24                    | log-signal | `log_by_lua` | `$status` (= `limit_conn_status`)       | Observability |
| 8  | Накопленный по IP / /24 счётчик `slow_client`/`conn_flood` указывает на повторного нарушителя                  | сигнал в reputation (D14 subnet/IP) → D15 → при достаточной тяжести эскалация в edge-ACL feed | log-signal | `log_by_lua` → reputation | счётчики `bac_log` + D14 | Observability  |

## C. Slow-attacks — policy-ручка (опционально)

Под `attack_mode` / повышенной strictness — более жёсткая зона `limit_conn` и
ниже таймауты. ⚠️ **Честное ограничение:** nginx-директивы нельзя менять
per-request из Lua. Реализация — `map`-driven выбор зоны per-host либо грубый
global-toggle, **не** плавная per-request подстройка. Может не делаться, если
Baseline + Observability уже закрывают риск.

| #  | Если…                                                                                                                       | То…                                                                                             | Категория            | Где живёт | Источник                                       | Этап         |
| -- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------- | --------- | ---------------------------------------------- | ------------ |
| 9  | Для host'а `policy[host].attack_mode=on` (или повышенная strictness)                                                        | через `map` для этого host'а выбирается более жёсткая зона `limit_conn` и/или меньшие таймауты  | mitigation-directive | nginx     | `policy` (`attack_mode`/strictness) → `map`    | Policy-ручка |

## D. HTTP/2 DoS — mitigation (билд + директивы)

В основном пропатченный билд + пара директив. Frame-уровневые атаки
(Rapid Reset CVE-2023-44487 и родня) до HTTP-семантики не доходят и каскадом
не видны вовсе.

| #  | Если…                                                                                                                         | То…                                                                                                       | Категория            | Где живёт | Источник                                  | Этап                    |
| -- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------- | --------- | ----------------------------------------- | ----------------------- |
| 10 | Клиент дёшево создаёт и тут же отменяет HTTP/2-стримы (reset без завершённого запроса) сверх порога                          | пропатченный nginx (≥ 1.25.3) считает сброшенные стримы и рвёт соединение при превышении                 | mitigation-directive | build     | версия OpenResty/nginx ≥ 1.25.3           | HTTP/2 mitigation-аудит |
| 11 | Число одновременных HTTP/2-стримов в соединении превысило `http2_max_concurrent_streams` (дефолт 128, тюнится)               | nginx ограничивает число параллельных стримов                                                             | mitigation-directive | nginx     | директива `http2_max_concurrent_streams`  | HTTP/2 mitigation-аудит |
| 12 | CONTINUATION / PING / SETTINGS flood превышает пороги, заданные версией билда                                                | пропатченный nginx применяет защиту по этим порогам                                                       | mitigation-directive | build     | пороги по версии билда                     | HTTP/2 mitigation-аудит |

## E. HTTP/2 DoS — h2-abuse как сигнал (опционально)

Зависит от наличия HTTP/2-fingerprint-спайка (E2). Детект-ассист, **не**
митигация: frame-митигация остаётся в nginx, fp лишь даёт способ видеть
аномалию.

> ⚠️ E3 (DoS-mitigation, Rapid Reset) ≠ E2 (HTTP/2 fingerprint, идентификация
> клиента / анти-JA4-ротация). Разные слои задачи.

| #  | Если…                                                                                                                | То…                                                                                  | Категория  | Где живёт                  | Источник                          | Этап                 |
| -- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ---------- | -------------------------- | --------------------------------- | -------------------- |
| 13 | HTTP/2-fingerprint-спайк (E2) видит аномальные SETTINGS/stream-паттерны соединения                                   | сигнал h2-abuse в reputation/score (рядом со `slow_client`/`conn_flood`), verdict не эмитится | tag | reputation (через fp-спайк) | HTTP/2 fingerprint (E2)            | h2-abuse как сигнал  |

## Сводка: что на каком этапе появляется

| Этап                        | Появляется                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Baseline-директивы**      | таймауты `client_header_timeout`/`client_body_timeout`/`send_timeout` (→408), `limit_conn` (→503), `keepalive_requests`/`keepalive_timeout` |
| **Observability**           | log-сигналы `slow_client`/`conn_flood` из `log_by_lua` → `bac_log` + счётчики по IP / /24 → reputation (D14) |
| **Policy-ручка**            | `map`-driven ужесточение `limit_conn`/таймаутов под `attack_mode`/strictness (опц., coarse, не per-request) |
| **HTTP/2 mitigation-аудит** | фиксация билда ≥ 1.25.3, `http2_max_concurrent_streams`, пороги CONTINUATION/PING/SETTINGS              |
| **h2-abuse как сигнал**     | h2-fp-аномалия как репутационный сигнал (опц., зависит от HTTP/2 fingerprint-спайка)                    |

## Границы (что эти правила НЕ делают)

- **Не блокируют из Lua.** Реальный отказ всегда у nginx/билда; Lua только
  наблюдает (log-фаза) и питает репутацию.
- **Не ловят волюметрику L3/L4** (SYN/UDP/амплификация) — хендшейк к этому
  моменту уже состоялся, это вне OpenResty. Максимум — контракт edge-ACL feed.
- **Не дают adaptive per-request лимиты** — nginx-директивы статичны на конфиг,
  policy-ручка переключает зоны грубо (per-host map / global toggle).
