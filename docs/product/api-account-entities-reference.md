# API & Account Protection — справочник сущностей

Термины и определения понятий оси защиты от абьюза аккаунтов и API + таблицы всех сущностей: стадии, ключи идентичности, профили, каталоги, теги, поля лога, перечисления. Источник правды по поведению — [api-account-protection-spec.md](api-account-protection-spec.md); каталог правил в формате «если → то» — [api-account-rules-reference.md](api-account-rules-reference.md); структура конфигов — [api-account-config-templates.md](api-account-config-templates.md).

**Статус:** проектный контракт (целевое поведение), предшествует реализации. Что уже в стенде — сверяй с [PROGRESS.md](../../PROGRESS.md) и кодом.

> **PII/security (сквозной инвариант).** Все ключи идентичности (username, token/API-key) используются и пишутся в лог **только в хешированном виде** (HMAC/sha256), никогда сырьём. **Пароль никогда не логируется, не хранится и не инспектируется.**

## Термины

| Термин                          | Определение                                                                                                                                                                                                                                                            |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Идентичность (identity)**     | Кто стоит за запросом на уровне приложения — аккаунт (username) или API-ключ. Эдж по умолчанию identity-blind: `verdict.lua` видит IP/fp/UA/Host/path/заголовки, но не «какой аккаунт» и не «какой ключ». Идентичность вычисляется стадией identity-extraction.          |
| **Ключ идентичности**           | Нормализованное хешированное значение (hashed username или hashed api key), которое identity-extraction кладёт в `ctx`. Используется профилями P2 и reputation как ключ счётчиков — ровно как `rate_tls_fp` кеит на fp. Сырьё (открытый username/токен) не сохраняется.   |
| **Стадия извлечения идентичности (identity-extraction)** | Лёгкая стадия каскада перед `rate_limits`, активная только на auth/API-путях. Извлекает и хеширует ключ. Вердикт сама не выносит — фундамент для остальных компонентов оси.                                                                                              |
| **Профиль (rate-профиль)**      | Именованный набор окон GCRA на движке `rate_limit.lua`. Ось вводит профили по идентичности (`rate_login_per_account`, `rate_api_key`) рядом с существующими сетевыми (`rate_ip`, `rate_tls_fp` и т.д.).                                                                  |
| **Failed-auth feedback**        | Обратная связь из ответа origin: чтение `$status` (401/403) в log/response-фазе, классификация success/fail и накопление доли неуспешных логинов. Не hot-path-проверка. Прецедент — паттерн D12.                                                                          |
| **Auth-endpoint config**        | Per-host декларация, какие пути считать login/register/API (`auth_login_paths` / `auth_register_paths` / `api_paths`, glob). Включает identity-extraction и чтение тела только там, где нужно. Расширяет модель `is_api_path(uri, patterns)`.                              |
| **`endpoint_class(uri)`**       | Классификатор эджа, который по URI возвращает класс пути (login / register / api / прочее) на основе auth-endpoint config. Им гейтятся identity-extraction и профили P2.                                                                                                  |
| **Graceful skip**               | Если ключ идентичности извлечь не удалось, зависящие профили не срабатывают, а запрос продолжает каскад без ошибки. Тот же паттерн, что `fp_usable`-guard у `rate_tls_fp`.                                                                                               |
| **`policy.enforce`**            | Mode-gate оси: определяет, исполняется ли вердикт физически (challenge / 429) или только пишется в лог (наблюдательный режим). Финальный выбор challenge↔block — по strictness, как у существующих rate-правил.                                                            |
| **disposable-email домен**      | Домен одноразовой почты. Каталог `disposable_email_domains` доставляется через Channel C (как `ua_blacklist`, ADR-006) и даёт сигнал фейк-регистрации. Не путать с breached-password проверкой (бэкенд).                                                                  |
| **Channel C**                   | Доставка runtime-data (каталоги) с backend на эдж. Используется для `disposable_email_domains` (ADR-006).                                                                                                                                                                |
| **B10 Policy API**              | API управления policy, через который декларируются массивы auth-путей (PATCH массивов `auth_login_paths` / `auth_register_paths` / `api_paths`).                                                                                                                          |

## Стадии (этапы каскада, затронутые осью)

Ось не добавляет новый слой каскада, а встраивается в существующий поток:
`hygiene → reputation → tls_fp → [identity-extract] → rate_limits → verification` плюс log/response-фаза.

| Стадия / фаза          | Роль в оси                                                                                                       | Активна где                                            | Компонент            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | -------------------- |
| `identity-extract`     | Извлекает и хеширует ключ идентичности, кладёт в `ctx`. Здесь же — опц. disposable-email сигнал (P5)             | только на путях из auth-endpoint config                | identity-extraction  |
| `rate_limits`          | Новые профили по идентичности рядом с сетевыми; enforcement через `policy.enforce`                               | весь каскад, но профили P2 — только при наличии ключа  | per-key profiles     |
| `verification`         | Step-up challenge/strictness по накопленным сигналам auth-абьюза (`challenge`/`attack_mode`)                     | как в базовом каскаде                                  | per-key profiles, P3 |
| log/response-фаза      | Failed-auth feedback: `log_by_lua`/`header_filter`, чтение `$status`, накопление failed-ratio                   | login-пути                                             | failed-auth feedback |

## Ключи идентичности

| Ключ               | Откуда извлекается                                                          | Форма в `ctx` и логе      | Кто использует                                | PII-инвариант                  |
| ------------------ | -------------------------------------------------------------------------- | ------------------------- | --------------------------------------------- | ------------------------------ |
| **hashed username**| login/register-форма (form-urlencoded / JSON тело) на login-путях          | HMAC/sha256, никогда сырьём | `rate_login_per_account`, failed-auth feedback, reputation | хешируется до использования и записи |
| **hashed api key** | `Authorization` / `X-API-Key` / query на auth/API-путях (bearer/API-key)   | HMAC/sha256, никогда сырьём | `rate_api_key`, reputation                    | хешируется до использования и записи |
| **пароль**         | — (не извлекается)                                                          | **не логируется, не хранится, не инспектируется** | никто                          | значение оси не нужно          |

## Профили rate-limit (на движке `rate_limit.lua`)

GCRA-профили (`gcra` / `windows` / shared_dict-ячейки). Профили оси отличаются от сетевых только источником ключа.

| Профиль                   | Ключ              | Что ловит                                                                | Действие при превышении                                  | Тег                       |
| ------------------------- | ----------------- | ------------------------------------------------------------------------ | -------------------------------------------------------- | ------------------------- |
| `rate_login_per_account`  | hashed username   | Стаффинг, размазанный по многим аккаунтам; targeted brute force одного   | `challenge` или `block` (429) по `policy.enforce`/strictness | `account:cred_stuffing`   |
| `rate_api_key`            | hashed api key    | Abuse одного ключа с многих IP; scraping/enumeration; leaked-key         | `block` (429) или `challenge` по `policy.enforce`/strictness | `api:key_abuse`           |

Оба профиля делают **graceful skip** при отсутствии ключа из identity-extraction (как `fp_usable`-guard). Сетевые профили (`rate_ip`/`rate_ip_ua`/`rate_api`/`rate_tls_fp`/`rate_scan_urls`) при этом продолжают работать.

## Каталоги (доставляются на эдж)

| Имя                       | Что внутри                                            | Доставка                              | Используется в       | Статус скоупа           |
| ------------------------- | ----------------------------------------------------- | ------------------------------------- | -------------------- | ----------------------- |
| `disposable_email_domains`| Set доменов одноразовой почты                         | Channel C (как `ua_blacklist`), ADR-006 | breached-cred (P5)   | опционально (edge-часть P5) |

> **Что НЕ каталог эджа.** Брешь-листы паролей (breached-password) — бэкенд-функция (ADR-005), не Lua hot-path. Эдж пароль не валидирует; граница edge↔backend фиксируется при внедрении P5.

## Теги оси (информационные — verdict не эмитят, копятся в `tags` через `bac_log`)

Namespace по поверхности (`account:` / `api:`). Влияют на решение только косвенно (комбинируются на верификации / аналитика).

| Код                       | Где появляется      | Что означает                                                                                              | Источник             |
| ------------------------- | ------------------- | --------------------------------------------------------------------------------------------------------- | -------------------- |
| `account:cred_stuffing`   | `rate_limits` (P2)  | Сработал `rate_login_per_account`: всплеск попыток логина по аккаунтам — credential stuffing / brute force | per-key profiles     |
| `api:key_abuse`           | `rate_limits` (P2)  | Сработал `rate_api_key`: abuse одного API-ключа (scraping/enumeration/leaked-key)                          | per-key profiles     |
| `account:auth_fail_spike` | log/response (P3)   | Всплеск доли неуспешных логинов (401/403) по hashed-account или IP-/24                                     | failed-auth feedback |

**Формат тега:** `<surface>:<short_name>`. Пишутся в общее поле `tags` (массив) JSON-лога `bac_log`, рядом с тегами основного каскада.

## Поля JSON-лога (специфичные для оси / переиспользуемые)

Ось переиспользует общую схему `bac_log`. Ниже — поля, которые она наполняет или интерпретирует.

| Поле               | Тип             | Описание (в контексте оси)                                                                                                                       | Когда заполнено                          |
| ------------------ | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| `status`           | int             | HTTP status ответа origin. На login-путях 401/403 классифицируются как failed-auth (вход P3)                                                       | всегда                                   |
| `verdict`          | string (enum)   | Решение по запросу. Для оси — `block` / `challenge` / `pass` (по `policy.enforce`/strictness)                                                      | всегда                                   |
| `rule`             | string          | Код сработавшего профиля оси (`rate_login_per_account` / `rate_api_key`)                                                                            | при срабатывании профиля P2              |
| `tags`             | array of string | Теги оси (`account:cred_stuffing` / `api:key_abuse` / `account:auth_fail_spike`) рядом с тегами каскада                                            | всегда (может быть `[]`)                 |
| hashed-account     | string          | Hashed username из identity-extraction. **Только HMAC/sha256**, никогда сырьём                                                                     | на login-путях, если username извлечён   |
| hashed-key         | string          | Hashed api key из identity-extraction. **Только HMAC/sha256**, никогда сырьём                                                                      | на auth/API-путях, если ключ извлечён    |
| (пароль)           | —               | **Не логируется ни в каком виде**                                                                                                                  | никогда                                  |

## Перечисления (enums)

### Класс эндпоинта — результат `endpoint_class(uri)`

| Значение      | Что значит                                                  | Эффект                                                                 |
| ------------- | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| `login`       | Путь из `auth_login_paths`                                  | identity-extraction (username, чтение тела), профиль `rate_login_per_account`, failed-auth feedback |
| `register`    | Путь из `auth_register_paths`                               | identity-extraction (username/email), disposable-email сигнал (P5)    |
| `api`         | Путь из `api_paths`                                         | identity-extraction (API-key/bearer), профиль `rate_api_key`          |
| прочее        | Путь не объявлен                                            | стадия identity-extraction пропускается, тело не читается             |

### `verdict` оси (подмножество базового каскада)

| Значение     | Что значит для оси                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------- |
| `pass`       | Профили/сигналы не сработали (или нет ключа — graceful skip), запрос идёт дальше                     |
| `block`      | Профиль по идентичности превышен и `policy.enforce` исполняет блок → 429 (как rate_limit 429)        |
| `challenge`  | Step-up верификация (для браузерного клиента на login-пути). Для API на JS-challenge не опираемся    |

### `policy.enforce` — режим исполнения

| Значение      | Поведение                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| наблюдательный| Профили/сигналы считаются и пишутся в лог, физически с запросом ничего не делается (mode-gated)         |
| активный      | Вердикт исполняется: `challenge` / 429 по strictness                                                    |

## Границы оси (⛔ это бэкенд, не эдж)

Не сущности эджа — перечислены, чтобы не путать скоуп.

| Сущность / сценарий              | Почему не эдж                                                                  | Где решается                |
| -------------------------------- | ----------------------------------------------------------------------------- | --------------------------- |
| **ATO** (аномальный успешный вход)| Эдж не знает истории аккаунта; даёт лишь fp/geo-контекст                       | Бэкенд (ADR-005)            |
| **Business-logic abuse**         | Нужен app-контекст (скальпинг, купоны)                                         | Приложение клиента / бэкенд |
| **Breached-password validation** | Полная проверка пароля по брешь-листу — бэкенд-функция, не Lua hot-path        | Бэкенд (ADR-005)            |
