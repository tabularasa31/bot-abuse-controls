# DDoS-защита — словарь сущностей

Канонический словарь терминов, директив, тегов, полей лога, перечислений и
контрактов DDoS-слоя по всем трем подслоям. Контракт поведения —
[ddos-spec.md](ddos-spec.md); правила — [ddos-rules-reference.md](ddos-rules-reference.md).

---

## 1. Подслои и общие термины

| Термин | Определение |
| --- | --- |
| **L7 application-layer (rate-based)** | DDoS по частоте HTTP-запросов; защита — каскад (rate-limit/challenge/attack_mode) + адаптивность (репутация, авто-режим, hot-list). |
| **Connection/protocol-level DDoS** | Класс DDoS, не сводящийся к частоте запросов и потому невидимый для rate-limit-каскада: slow-attacks и HTTP/2 DoS. |
| **Slow-attack** | Атака на уровне TCP-соединения (slowloris / slow POST / slow read): много соединений, медленно/никогда не завершающих передачу, выедающих слоты воркеров. |
| **HTTP/2 DoS** | Атака на уровне HTTP/2-фреймов (Rapid Reset, CVE-2023-44487 и родня): дешевое создание + отмена стримов, дорогое для сервера. |
| **Волюметрика L3/L4** | SYN/UDP-флуд, амплификация — насыщение канала/стека до рукопожатия. Митигируется вне периметра прокси. |
| **Митигация** | Реальный отказ/обрыв. На connection/protocol — nginx-директива или свойство билда (не Lua). На L7 — rate-limit/challenge/drop по политике. |
| **Наблюдение (log-сигнал)** | Лог-событие, которое Lua-хук в log-фазе пишет, увидев результат nginx-дропа. Это наблюдение постфактум, не вердикт. |
| **Общий сток репутации** | Единый артефакт, куда стекаются повторные нарушители (IP/24/ASN) из всех подслоев; повышает строгость на L7 и питает edge-ACL feed. |

## 2. L7 rate-based — сущности

| Сущность | Определение |
| --- | --- |
| **GCRA-профиль** | per-request rate-limit по ключу (IP, IP+UA, API-путь, TLS-отпечаток, recon-URL) со скользящим окном. База L7, из каскада. |
| **attack_mode** | per-host тумблер повышенной строгости (ниже пороги, агрессивнее challenge). Может быть установлен **вручную** или **авто**. |
| **авто-attack-mode** | авто-взвод `attack_mode` по «плохому» трафику относительно базлайна хоста (боты / solve-rate ≈ 0 / латентность origin), с гистерезисом снятия. Ручная установка приоритетна. |
| **базлайн хоста** | нормальный профиль трафика хоста, относительно которого измеряется «плохой» трафик для авто-режима. |
| **subnet/IP/ASN-репутация** | глобальный (виден всем тенантам) soft-артефакт: повторные нарушители, агрегированные по IP, /24-подсети, ASN (особенно datacenter-пулы). Повышает score/строгость, сам не блокирует. |
| **transient subnet challenge→drop** | временная эскалация challenge → drop для /24 под `attack_mode` хоста при плохой репутации и solve-rate ≈ 0; реактивные per-/24 счетчики, TTL + авто-снятие. |
| **кросс-тенантный hot-list** | short-TTL список активных атакующих (fp/subnet), пред-взводящий все эджи (challenge-first, ниже порог). Глобальная репутация, per-tenant enforcement. Высокий порог промоута. |
| **быстрый / медленный tier** | быстрый — short-TTL hot-list (секунды реакции на пивот ботнета); медленный — устойчивые глобальные каталоги, доставляемые штатным путем. |
| **solve_rate** | доля решенных challenge по источнику/отпечатку. ≈ 0 при многих выданных → сильный сигнал бота под флудом. |

## 3. Connection/protocol — nginx-директивы и зоны (реальная митигация)

| Директива / объект | Что делает | Семейство | Целевое значение |
| --- | --- | --- | --- |
| `client_header_timeout` | таймаут приема строки/заголовков; превышение → обрыв, `408` | slow | 10–15s |
| `client_body_timeout` | таймаут между чтениями тела; превышение → обрыв, `408` | slow | 10–15s |
| `send_timeout` | таймаут между записями ответа (slow read); превышение → обрыв | slow | 10–15s |
| `limit_conn` (+ зона) | cap одновременных соединений по `$binary_remote_addr`; лишние — отказ | slow | зона по IP |
| `limit_conn_status` | код ответа на отказ `limit_conn` | slow | `503` |
| `keepalive_requests` | лимит запросов на keepalive-соединение; сверх — закрытие | slow | ограничить idle-удержание |
| `keepalive_timeout` | время простоя idle-keepalive до закрытия | slow | ограничить idle-удержание |
| `large_client_header_buffers` | буферы под крупные заголовки (против header-abuse) | slow | осознанно |
| `client_max_body_size` | лимит размера тела на прокси-путях | slow | осознанный per-path |
| `http2_max_concurrent_streams` | лимит одновременных HTTP/2-стримов в соединении | HTTP/2 | тюнится |
| Reset-flood guard (build) | подсчет сброшенных-без-завершения стримов и обрыв (Rapid Reset) | HTTP/2 | билд ≥ 1.25.3 |
| Frame-flood guard (build) | пороги CONTINUATION/PING/SETTINGS flood | HTTP/2 | по версии билда |

## 4. Connection/protocol — теги (информационные, в лог-событии)

| Тег | Когда появляется | Источник |
| --- | --- | --- |
| `slow_client` | таймаут заголовков/тела/чтения → `$status=408` | log-фаза, `$status`/`$request_time` |
| `conn_flood` | отказ `limit_conn` → `$status` = `limit_conn_status` (`503`) | log-фаза, `$status` |
| `h2_abuse` | аномальный HTTP/2 SETTINGS/stream-паттерн (опц., если доступна h2-идентификация) | log-фаза / репутация |

Формат тега — `<namespace>:<short_name>`, как у тегов каскада. Отличие: ставится в
log-фазе постфактум, описывает уже состоявшийся nginx-дроп, судьбу запроса не решает.

## 5. Connection/protocol — поля лог-события (log-фаза)

| Поле | Тип | Описание | Источник |
| --- | --- | --- | --- |
| `status` | int | HTTP-код в log-фазе. `408` → кандидат на `slow_client`; `503` → кандидат на `conn_flood` | `$status` |
| `request_time` | float | длительность обработки (сек); высокое при `408` — индикатор медленного клиента | `$request_time` |
| `connection_requests` | int | сколько запросов обслужило keepalive-соединение (keepalive-abuse) | `$connection_requests` |
| `tags` | array | namespace-теги connection/protocol-сигналов | log-хук |

## 6. Перечисления

### HTTP-коды отказа (connection/protocol)

| Код | Когда | Триггер | Тег |
| --- | --- | --- | --- |
| `408` | таймаут приема заголовков/тела или slow read | `client_header_timeout` / `client_body_timeout` / `send_timeout` | `slow_client` |
| `503` | отказ по cap одновременных соединений | `limit_conn` (через `limit_conn_status`) | `conn_flood` |

### Категория объекта правила

| Значение | Что это | Кто исполняет |
| --- | --- | --- |
| `rate-rule` / `adaptive` | L7-логика поверх каскада (может влиять на судьбу запроса) | каскад + аналитика |
| `mitigation-directive` | реальный отказ/обрыв соединения | nginx / build |
| `log-signal` | лог-событие из log-фазы по факту дропа | log-хук |
| `tag` | namespace-метка на событии (судьбу запроса не решает) | log-хук |
| `escalation` | поставка нарушителя в репутацию / edge-ACL feed | аналитика / контракт |

### attack_mode — источник установки

| Значение | Что это |
| --- | --- |
| `manual` | установлен оператором; приоритетен над авто |
| `auto` | взведен авто-детектом по «плохому» трафику; снимается с гистерезисом; не перебивает `manual` |

## 7. Контракт edge-ACL feed (эскалация в сетевой слой)

| Свойство | Значение / контракт |
| --- | --- |
| Назначение | эскалация подтвержденных нарушителей (IP / /24) в сетевой слой, который прокси не достает |
| Вход | накопленные по IP / /24 счетчики и репутация из L7 и connection/protocol сигналов |
| Граница | волюметрика L3/L4 митигируется вне периметра прокси — рукопожатие к этому моменту еще не состоялось |
| Максимум прокси | поставка кандидатов в feed; сетевую митигацию выполняет внешний слой |

## 8. Глоссарий

- **slowloris / slow POST / slow read** — три подвида slow-attack: медленный недослав
  заголовков, тела и медленное вычитывание ответа соответственно.
- **Rapid Reset (CVE-2023-44487)** — HTTP/2-DoS через массовое создание + мгновенную
  отмену стримов; митигируется пропатченным билдом (≥ 1.25.3).
- **log-фаза** — фаза обработки запроса после отправки ответа, единственная точка, где
  слой наблюдения видит результат connection/protocol-дропа.
- **гистерезис** — разные пороги на взвод и снятие авто-режима, чтобы он не дребезжал
  на границе.
- **edge-ACL feed** — контракт поставки нарушителей в сетевой слой для случаев выше
  периметра прокси (волюметрика).
