# Connection/Protocol-level DDoS — справочник сущностей

Термины и определения + таблицы всех сущностей этой оси: nginx-директивы и зоны,
теги, новые поля лога, перечисления/статусы, контракт edge-ACL feed. Источник правды
по поведению — [connection-protocol-ddos-spec.md](connection-protocol-ddos-spec.md);
этот документ — словарь.

**Сопутствующие материалы:**
[connproto-ddos-rules-reference.md](connproto-ddos-rules-reference.md) — правила/сигналы
в формате «если условие → действие»;
[connproto-ddos-config-templates.md](connproto-ddos-config-templates.md) — структура
nginx-директив и порогов.

**Статус:** проектный контракт (целевое поведение), предшествует реализации.

**Чем эта ось особенная.** В отличие от каскада ([entities-reference.md](entities-reference.md)),
здесь нет стадии каскада и нет access-фазовых вердиктов. Slow-клиент и сброшенный
HTTP/2-стрим до `access_by_lua` не доходят. Поэтому сущности этой оси — это
**nginx-директивы/зоны** (реальная митигация), log-фазовые сигналы и теги
(наш слой наблюдения через `log_by_lua` → `bac_log`) и контракт эскалации в общий
DDoS-сток. Запись в `bac_log` здесь — наблюдение постфактум, а не вердикт по запросу.

## Термины

| Термин                          | Определение                                                                                                                                                                                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Connection/protocol-level DDoS** | Класс DDoS, который не сводится к частоте HTTP-запросов и потому невидим для rate-limit-слоя каскада (L4). Два семейства: slow-attacks и HTTP/2 DoS.                                                                                                              |
| **Slow-attack**                 | Атака на уровне TCP-соединения (slowloris / slow POST / slow read): много соединений, которые медленно или никогда не завершают передачу, выедая слоты воркеров.                                                                                                     |
| **HTTP/2 DoS**                  | Атака на уровне HTTP/2-фреймов (Rapid Reset, CVE-2023-44487 и родня): дешёвое для клиента создание+отмена стримов, дорогое для сервера.                                                                                                                              |
| **Митигация (mitigation)**      | Реальный отказ/обрыв соединения. На этой оси выполняется nginx-директивой или свойством пропатченного билда, не Lua. Вердикта каскада не эмитит.                                                                                                             |
| **mitigation-directive**        | nginx-директива (или build-гарантия), которая обрывает/ограничивает соединение: таймаут → 408, `limit_conn` → код `limit_conn_status`, frame-flood guard билда.                                                                                                     |
| **log-signal**                  | Событие `bac_log`, которое `log_by_lua`-хук эмитит, увидев результат nginx-дропа в log-фазе. Это наблюдение, а не действие — запрос уже оборван nginx.                                                                                                               |
| **Тег (tag)**                   | namespace-метка на событии `bac_log` (`slow_client` / `conn_flood` / h2-abuse сигнал). Не влияет на судьбу запроса (он уже оборван); питает дашборд и репутацию. Формат — `<namespace>:<short_name>`, как у тегов каскада.                                          |
| **Зона `limit_conn`**           | Именованная shared-memory зона nginx, в которой считаются одновременные соединения по ключу (целевой ключ — `$binary_remote_addr`). При превышении cap новые соединения отклоняются.                                                                                |
| **`limit_conn_status`**         | HTTP-код, которым nginx отвечает на отказ по `limit_conn`. Целевое значение — `503`.                                                                                                                                                                                |
| **log-фаза (`log_by_lua`)**     | Фаза обработки запроса nginx после отправки ответа, в которой исполняется наш Lua-хук. Единственная точка, где BAC-слой видит результат connection/protocol-дропа.                                                                                                  |
| **`bac_log`**                   | Контракт логирования BAC-слоя (тот же, что используют hygiene/reputation). Сюда `log_by_lua` пишет событие connection/protocol-дропа с тегом.                                                                                                                       |
| **Эскалация в репутацию**       | Повторные нарушители по IP / /24 уходят в общий DDoS-сток: D14 (subnet/IP reputation) → D15 → при достаточной тяжести — edge-ACL feed (сетевой слой).                                                                                                               |
| **edge-ACL feed**               | Контракт эскалации в сетевой слой (roadmap §4.3) для случаев, которые выше OpenResty (волюметрика L3/L4). Наш максимум по волюметрике — поставка в этот feed, сама митигация — вне OpenResty.                                                                       |
| **Policy-ручка**                | Опциональное ужесточение `limit_conn`/таймаутов под `attack_mode`/повышенной strictness. Реализуется `map`-driven выбором зоны per-host или грубым global-toggle — не per-request (nginx-директивы нельзя менять per-request из Lua).                            |
| **HTTP/2 fingerprint (E2)**     | Отдельная задача идентификации HTTP/2-клиента (анти-JA4-ротация). Не митигация. Может опционально дать сигнал h2-abuse для репутации. Не путать с HTTP/2 DoS-mitigation (E3).                                                                                   |

## nginx-директивы и зоны (реальная митигация)

| Директива / объект              | Что делает                                                                                                  | Семейство атак | Где живёт | Целевое значение / примечание                                  |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------- | -------------- | --------- | -------------------------------------------------------------- |
| `client_header_timeout`         | Таймаут на приём строки запроса и заголовков; при превышении — обрыв, `408`                                  | slow           | nginx     | срезать до 10–15s (дефолт 60s)                                 |
| `client_body_timeout`           | Таймаут между чтениями тела запроса; при превышении — обрыв, `408`                                           | slow           | nginx     | срезать до 10–15s                                              |
| `send_timeout`                  | Таймаут между записями ответа клиенту (защита от slow read); при превышении — обрыв                          | slow           | nginx     | срезать до 10–15s                                              |
| `limit_conn` (+ зона)           | Cap одновременных соединений по ключу `$binary_remote_addr`; лишние — отклоняются                            | slow           | nginx     | зона по IP; cap — системная константа                          |
| `limit_conn_status`             | Код ответа на отказ по `limit_conn`                                                                          | slow           | nginx     | `503`                                                          |
| `keepalive_requests`            | Лимит запросов на одно keepalive-соединение; сверх — соединение закрывается                                  | slow           | nginx     | ограничивает удержание idle-слотов                            |
| `keepalive_timeout`             | Время простоя idle-keepalive до закрытия                                                                     | slow           | nginx     | ограничивает удержание idle-слотов                            |
| `large_client_header_buffers`   | Буферы под крупные заголовки; осознанная настройка против header-abuse                                       | slow           | nginx     | —                                                              |
| `client_max_body_size`          | Лимит размера тела на прокси-путях                                                                           | slow           | nginx     | осознанный per-path (в стенде задан на solver-локации)        |
| `http2_max_concurrent_streams`  | Лимит одновременных HTTP/2-стримов в соединении                                                              | HTTP/2         | nginx     | дефолт 128, тюнится                                            |
| `http2 on`                      | Включение HTTP/2 на listener (предусловие для h2-митигаций)                                                  | HTTP/2         | nginx     | в стенде уже включено                                         |
| Reset-flood guard (build)       | Подсчёт сброшенных-без-завершения стримов и обрыв соединения при превышении (Rapid Reset)                    | HTTP/2         | build     | OpenResty/nginx ≥ 1.25.3                                       |
| Frame-flood guard (build)       | Пороги CONTINUATION/PING/SETTINGS flood                                                                      | HTTP/2         | build     | по версии билда                                               |

## Теги (информационные) — копятся в `bac_log`, verdict не эмитят

| Тег              | Когда появляется                                                            | Где живёт    | Источник                                |
| ---------------- | --------------------------------------------------------------------------- | ------------ | --------------------------------------- |
| `slow_client`    | таймаут заголовков/тела/чтения → `$status=408` (`client_*_timeout`/`send_timeout`) | `log_by_lua` | `$status` / `$request_time`             |
| `conn_flood`     | отказ `limit_conn` → `$status` = `limit_conn_status` (целевой `503`)        | `log_by_lua` | `$status`                               |
| h2-abuse сигнал  | аномальный HTTP/2 SETTINGS/stream-паттерн (опционально, зависит от E2)        | `log_by_lua` / reputation | HTTP/2 fingerprint (E2)        |

**Формат тега:** `<namespace>:<short_name>`, как у тегов каскада — namespace позволяет
добавлять сигналы без конфликта имён. Отличие от вердикта каскада: тег ставится в
log-фазе, постфактум, и описывает уже состоявшийся nginx-дроп, а не решает судьбу запроса.

## Новые поля лога (event `bac_log`, log-фаза)

`log_by_lua`-хук читает nginx-переменные log-фазы и кладёт их в событие. Видно только то,
что nginx отдаёт в log-фазе; сам процесс «цежения» соединения в реальном времени не виден.

| Поле                    | Тип            | Описание                                                                                                                  | Источник              |
| ----------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------- |
| `status`                | int            | HTTP-код в log-фазе. `408` → кандидат на `slow_client`; `limit_conn_status` (`503`) → кандидат на `conn_flood`            | `$status`             |
| `request_time`          | float          | Длительность обработки запроса (сек). Высокое значение при `408` — индикатор медленного клиента                           | `$request_time`       |
| `connection_requests`   | int            | Сколько запросов обслужило keepalive-соединение (полезно для keepalive-abuse)                                             | `$connection_requests` |
| `tags`                  | array of string | namespace-теги connection/protocol-сигналов: `slow_client` / `conn_flood` / h2-abuse                                     | `log_by_lua`          |

> Поля берутся из штатных nginx-переменных log-фазы (`$status`, `$request_time`,
> `$connection_requests`); событие пишется через тот же `bac_log`-контракт, что и
> hygiene/reputation, без новой стадии каскада.

## Перечисления / статусы

### HTTP-коды отказа (что отдаёт nginx)

| Код   | Когда                                                                  | Триггер-директива                                  | Тег          |
| ----- | ---------------------------------------------------------------------- | -------------------------------------------------- | ------------ |
| `408` | таймаут приёма заголовков/тела или slow read                           | `client_header_timeout` / `client_body_timeout` / `send_timeout` | `slow_client` |
| `503` | отказ по cap одновременных соединений                                  | `limit_conn` (через `limit_conn_status`)           | `conn_flood`  |

### Категория объекта оси

| Значение               | Что это                                                              | Кто исполняет        |
| ---------------------- | ------------------------------------------------------------------- | -------------------- |
| `mitigation-directive` | реальный отказ/обрыв соединения                                     | nginx / build        |
| `log-signal`           | событие `bac_log` из log-фазы по факту дропа                        | `log_by_lua`         |
| `tag`                  | namespace-метка на событии (`slow_client`/`conn_flood`/h2-abuse)    | `log_by_lua`         |

### Этапы внедрения (по порядку)

| Этап                        | Семейство | Зависит от                          |
| --------------------------- | --------- | ----------------------------------- |
| Baseline-директивы          | slow      | —                                   |
| Observability               | slow      | Baseline-директивы                  |
| Policy-ручка (опц.)         | slow      | Observability                       |
| HTTP/2 mitigation-аудит     | HTTP/2    | — (самостоятелен)                   |
| h2-abuse как сигнал (опц.)  | HTTP/2    | HTTP/2 fingerprint-спайк (E2)       |

## Контракт edge-ACL feed (эскалация в сетевой слой)

Не директива и не тег — контракт поставки повторных нарушителей в сетевой слой
(roadmap §4.3). Нужен для случаев выше OpenResty.

| Свойство                | Значение / контракт                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Назначение              | эскалация подтверждённых нарушителей (IP / /24) в сетевой слой, который OpenResty не достаёт                              |
| Вход                    | накопленные по IP / /24 счётчики `slow_client` / `conn_flood` через D14 (subnet/IP reputation) → D15                       |
| Граница                 | волюметрика L3/L4 (SYN/UDP/амплификация) митигируется вне OpenResty — хендшейк к этому моменту уже состоялся (reality-3) |
| Наш максимум по волюметрике | поставка кандидатов в edge-ACL feed; саму сетевую митигацию выполняет внешний слой                                     |

## Глоссарий ключевых терминов

- **slowloris / slow POST / slow read** — три подвида slow-attack: медленный
  недослав заголовков, тела и медленное вычитывание ответа соответственно.
- **Rapid Reset (CVE-2023-44487)** — HTTP/2-DoS через массовое создание+мгновенную
  отмену стримов; митигируется пропатченным билдом (≥ 1.25.3).
- **`access_by_lua` / `log_by_lua`** — фазы nginx, где исполняется Lua. Каскад живёт в
  `access_by_lua`; наблюдение этой оси — в `log_by_lua` (после ответа).
- **`bac_log`** — общий контракт логирования BAC-слоя, переиспользуется без изменений.
- **`metrics.lua`** — модуль счётчиков BAC; принимает инкременты `slow_client`/`conn_flood`
  по IP / /24.
- **D14 / D15** — этапы общего reputation-стока DDoS (subnet/IP reputation и далее),
  куда питаются повторные нарушители этой оси.
- **reality-3** — класс «не наше / вне OpenResty» (волюметрика L3/L4); максимум — контракт
  edge-ACL feed.
