## Точка отсчёта (что уже есть, D1)

Цикл `analyze.py` → staging → active → auto-demote. **Score только ранжирует**, допуск
решают gates (purity-вето `human_share≤0.05`, volume, allowlist/verified, dedup) + intent
(`impersonator OR recon-on-non-generic`). Подтверждение наблюдением на staging, выход — по
неактивности (TTL). Источник — Loki через `antibot-analytics`, выход — draft-PR в `catalogs/`.

Три наблюдения, задающие вектор:
1. Решение строится на **одном измерении** — TLS-fp (JA4-like ClientHello). Fp ротируется дёшево.
2. Скоринг работает на **агрегатах по fp**, без поведенческого/временно́го измерения.
3. Уже копятся **сильные метки, которые в скоринг не возвращаются** — исходы challenge
   (`challenge_issued`/`challenge_solved`), clearance-результаты, `staging_match`.

## Направления

### #1 — Challenge-исход обратно в скоринг  ⭐ приоритет
Fp, который массово получает challenge и почти никогда его не решает (`solve_rate≈0` при
N выданных) — это near-ground-truth метка бота, сильнее любой статической эвристики.
Сигнал уже эмитится (C5: `antibot_challenge_issued_total` / `solved_total`), но никуда не течёт.
Идея: `solve_rate` по fp как (а) доп-сигнал score и (б) ускоренный gate staging→active.
Дешевле всего — надстройка над D1, новых стадий каскада не нужно. **Детальный дизайн — ниже/отдельным документом.**

### #2 — Расширить fp за пределы TLS
- **HTTP/2 fingerprint** (порядок SETTINGS-фреймов, WINDOW_UPDATE, псевдо-порядок заголовков) —
  ортогонален TLS, ломает дешёвую JA4-ротацию. Сейчас этого измерения нет вообще.
- Перекликается с бэклогом: **D2** (positive fp catalog: known-browser cipher hashes + version),
  **D3** (UA-version vs fp-version mismatch), **D4** (headless-каталог Playwright/Puppeteer/UDC).
  Связка D2+D3 ловит самопальные/headless стэки **без** словаря инструментов (mismatch вместо
  impersonator).

### #3 — Поднять единицу анализа выше отдельного fp
Сейчас блокируется fp. Ввести корреляцию **fp × IP/ASN-subnet × поведение**: один fp на /24
датацентра с recon — иное, чем тот же fp с тысяч резидентных IP. Subnet-level репутация +
защита от fp-ротации в пределах пула. reputation.lua уже знает ASN/geo — скоринг этим не пользуется.

### #4 — Поведенческие / временны́е сигналы
Score сейчас бинарно-аддитивный по статике. Добавить: межзапросные интервалы (ритмичность),
отсутствие человеческого разброса, навигационные графы (бот ходит по sitemap/recon, не по ссылкам).
Переводит детектор из сигнатурного в поведенческий — рычаг против low-and-slow ботов, которые
проходят rate-limit и не светят инструментальный fp.

### #5 — Робастность скоринга (anti-poisoning)
Цикл частично автоматический (draft-PR на HIGH) → атакуем. Злоумышленник может водить
«человеческий» трафик под целевым fp, чтобы поднять `human_share` и защитить fp от блока (или
загрязнить чужой fp). Продумать: устойчивость purity-вето к инъекции, диверсификацию источников
событий, daily-snapshot diff цепочки доказательств (уже отмечен как future-follow-up в blocklist-scoring.md).
